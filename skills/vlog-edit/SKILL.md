# vlog-edit

Workspace: `~/Documents/vlog-editing/` (git). Read before any edit:
- `docs/storytelling.md` — narration, structure, pacing, subtitle spec, music states. **No 流水账.**
- `docs/toolchain.md` — installed tools and every pitfall hit so far.
- `docs/music-sources.md` — free music sources and licenses.
- `docs/footage-sources.md` — free overlay / B-roll footage, and which transitions are generated in code instead.
- `docs/workflow.md` — the stages agreed with the user.
- `docs/publishing.md` — Xiaohongshu cover and caption, the account's cover style.

Talk to the user in Chinese. Product text in videos stays as the user writes it.

## Project layout

`projects/<trip>/` per trip: `ingest/` (clips.json, proxy/, sheets/, audio/, transcripts/), `edl/*.json`, `music/` (+ `LICENSES.md`), `render/`. Footage stays where it is. Media files are git-ignored.

## Stages

1. **Ingest** — `python3 scripts/ingest.py <project> --tz +08:00 <footage dir>...` (360p proxies, sheets, 16 kHz audio, GPS; skips LRV and our own renders; `--tz` = the trip's UTC offset, so iPhone `+0800` and shared copies' UTC times land on the same local clock as the camera's file names), then
   `PATH=/opt/homebrew/bin:$PATH python3 scripts/transcribe.py <project> "<prompt with place names>" --min 5` (word timestamps, hallucination blacklist; `--min` skips the 2–3 s Live Photo clips, each of which costs ~7 s of model overhead). Run both in background with `nohup`; they resume where they stopped. Proxy over HTTPS for FMA / web fetches: `HTTPS_PROXY=http://127.0.0.1:9090`.
2. **Look** — `python3 scripts/board.py <project> c001 c034 out.jpg` (3 frames per clip, 2 clips per row). Read every board before choosing anything; for hero shots make 1 fps strips; long underwater clips: read `ingest/sheets/<id>.jpg` (1 frame / 4 s) to find the highlights (fish schools, turtles). Build the trip skeleton (where/when) from boards + transcripts.
   - Motion: `~/.venvs/tts/bin/python scripts/motion.py <project>` (OpenCV; ~2 min for 200 clips) → `ingest/motion.json`: per second jitter, **roll** (deg/s — underwater "歪歪扭扭" is rotation, which the old translation-only `stability.py` could not see) and drone direction. The builder rejects shaky / rolling B-roll and back-and-forth drone moves and suggests steady windows; `b.steady()` and `vo(broll=[(clip, None)])` pick from them. Fish schools fool the estimate — look at a 2 fps strip and `b.allow_motion(clip, a, b, why)`.
   - Choosing B-roll (underwater above all): steady is not enough. It must be level (a body lying diagonally / a tilted frame is out - motion data cannot see a constant tilt, look at a 1 fps strip) and it must contain something (a person, fish, coral - not empty blue, a bubble cloud or bare wall texture). Rank every steady window of the day with `~/.venvs/tts/bin/python scripts/candidates.py <project> <out_prefix> <clips...> --dur 4.5`, look at the boards, then choose. Shots of the user filmed by a guide / buddy are the best material. Shots the user names are always used.
   - Footage that isn't the user's (odd file names / vertical phone video / not in their story) — ask before using it, never narrate it as their experience.
   - Duplicates: `python3 scripts/dedupe.py <project>` → `ingest/duplicates.json` (same footage under another name; the builder treats them as one clip).
   - Times: iPhone `IMG_*.MOV` without a creation date get their file mtime (= shooting time, checked against photo numbers). Shared copies from other people have transfer times — fix them with `Builder(times={...})`.
   - No drone on this trip but a big scene needs one: free stock aerials found in the built-in browser (Pexels), matched to the place and to the season / weather of the user's own shots, then `python3 scripts/add_stock.py <project> <file> <from> <to> --ref <clip:sec>... --url --author --license` colour-matches it to the user's footage and adds it as `s01`… (`docs/footage-sources.md` → 用户素材里没有的航拍).
   - Photos: `ingest/photos.json` (id, file, EXIF time) for the trip's photos; they fill gaps where video is thin (tarsier, fireflies).
3. **Story & outline** — per `storytelling.md`. Live lines come from transcripts with word timestamps; subtitle text is corrected by hand (ASR misspells places: 宿务, 薄荷岛). The user reviews the outline (several rounds) before any cutting.
   - Talk: `python3 scripts/clean_speech.py <project> <clip> <from> <to>` lists clean pieces (fillers, pauses, false starts removed); pick pieces by hand (repeats across a pause are not caught). English speech gets Chinese subtitles.
   - Every thing the narration names must be on screen at that moment — find it in the footage first (sardine storm: c143, not the wall clip). Can't find it → ask or cut the line. A line that doesn't fit its picture goes.
   - Pick the seconds where the subject is most visible (Bali: scan the dolphin clips at 1 fps, count dolphins per frame, use the pod and freeze its best frame as a photo). Every B-roll item must belong to what the paragraph is about — a snail photo slipped into the dolphins because it was shot the same morning. A visible thing the narration names but the footage lacks (the old 50,000 rupiah note) is shown from a public-domain image as a `news` card over the same place; source goes into the project's `news/SOURCES.md`.
   - The outline marks every no-narration moment ("【不配音】+ why") and every aerial ("【航拍】+ first / shape / end / title"), and what has to come from stock, so the user can change them before cutting (`storytelling.md` → 不配音的镜头, 航拍).
   - Two visits to one place become one sequence (Kelingking: evening on the top + next day down to the beach), joined by one narration line, `back=True`.
   - Names (routes, places, species, section titles) come from research, never invented: "传统路线" was made up; the route is the Bohol Countryside Tour / 陆地一日游.
   - Photos: never shirtless or otherwise unflattering / private ones; pick the clothed shots of a set.
4. **Narration** — the user records it. Script goes into the EDL as `vo` (shown as subtitles, music ducked under them, B-roll stretched to fit). No AI voice in a final cut. When the user gives a short trip summary, expand it into the whole film's script (per section), not just the opening.
   - Learn the trip background before writing any script: why this trip, who's in it, what was planned vs. unexpected, the one moment that mattered. Ask if it isn't in the footage.
   - **Write paragraphs, not lines** (`b.vo('一整段，带标点。', broll)`; a list = several paragraphs). One paragraph = what the user says in one breath, 10–60 s, ~80–90 characters typical, spoken style with connectives (然后 / 其实 / 可是 / 没想到). The builder cuts it into ≤16-wide subtitle lines and times them at the user's measured pace (4.5 syllables/s; 0.45 s after 。, 0.3 after ；, 0.15 after ，). v7's line-by-line script with 0.7 s + 0.6 s of padding per line made the user wait 1–2.6 s for every subtitle — "太散，不够饱满" — and that padding alone was 68 s of the 15-minute cut.
   - Not more narration — fuller narration: a reference 57-min film narrates only 13 % of its length, but every time it speaks it is a whole paragraph that goes fact → why → people → me. Give the film one through-line (a question or a wish set up early, frustrated midway, answered by the last line) and one recurring motif. Research the place (geography, history, culture, how people live) for the point where it meets the user's own experience. Method and examples: `storytelling.md` → 全片要有一条主线 / 旁白怎么写.
   - Feelings written in the user's voice get flagged for the user to correct; facts that sources disagree on are left out or hedged (据说).
   - **Copy must be vivid, not an itinerary** ("从乌布要翻过巴厘岛中部的山" was called 文学素养差): write what the body and eyes notice, local metaphors, a concrete scene instead of an aphorism. Run the whole draft past a "Chinese editor" subagent (picture / facts to keep / draft per paragraph, as in `projects/bali-2026/narration_v4_draft.md`), then check each suggestion against the facts; checklist in `storytelling.md` → 文案要有画面、有感受.
   - Jianying drafts the user saved are encrypted — their edits are invisible to us. Ask what they changed. Their recordings in the draft's `audio_record/*.aac` are plain audio and can be transcribed (pace, what they actually said).
5. **Music is the soul of the film** — read the music section of `storytelling.md` first. **The user picks the songs** (Jianying SVIP library etc.); I write the **cue sheet** (`storytelling.md` → 配乐表): one sonic palette for the whole film (two or three core instruments, a tempo range, one sentence of arc), 4–6 cues for 15–20 min, one per story section, and per cue: its job (score the subtext), start→turn→end feeling, genre → instruments → tempo → number of instruments (in that order), a pair of opposite words, entry / build / landing / exit, what to avoid; music-free stretches get a row with the reason. Bali v4's 11 unrelated songs changing 15 times read as "完全没有代入感". Publishing licence must cover Xiaohongshu (Jianying: only 全渠道 commercial music). **Never reuse songs from earlier episodes** (`docs/music-sources.md` keeps the per-episode list). When the user asks me to find music: free, cross-platform licence only, and measure every candidate with `~/.venvs/tts/bin/python scripts/music_check.py <tracks>` (drums, bass, brightness, distortion; thresholds in `storytelling.md` → 自己找歌时); record it in `music/LICENSES.md`.
   - **Music stops completely** (`b.music_out('why')`, not `low`) for: someone singing or playing live, a performance or dance with its own music, a place whose sound is the point (waterfall, waves, a night river with only paddles), quiet places (church), the user's breathing / a heavy line. Let those run long — a whole verse, 15–45 s. Every music-free stretch has a written reason.
   - Songs never run into each other: the old one fades out (1.5 s) at the end of its section, 1–3 s of natural sound, the new one enters on the first wide shot of the next section. The opening song comes back at the end (`storytelling.md` → 整体结构 → 收尾).
   - Search: `python3 scripts/fma_search.py <project>/music/fma ukulele underwater --download` (ONE word per query — multi-word queries return nothing; `--album <url>` downloads a whole album) (keeps only CC0 / CC BY, reads each track's own page, logs licences). Mixkit has no tropical / world tags. Pixabay blocks scripts — give the user titles to download. Proven per-scene picks: `docs/music-sources.md`. Pick by data: `~/.venvs/tts/bin/python scripts/music_profile.py <tracks>` (tempo, energy curve, biggest rises).
   - Never lay a near-silent stretch of a track under a montage.
   - Music-only change: `render_preview.py ... --reuse-video <previous render>` (picture fingerprint must match) — ~7 min instead of ~20.
   - Mix (automatic in the renderer): every song levelled to the same loudness first; under live speech the music sits ≥ 18 dB below the measured voice (verify fails < 15 dB); `ambient` shots play at 0.5 where no music plays; photos / drone shots in a music-free stretch need `bed=(clip, t)` natural sound — the builder rejects a shot with no sound and no music, verify rejects 1.5 s of silence.
   - Anchor the track's biggest entry (drums in, onset strength) on the most important cut: `music.start` = track time of the entry − (timeline time of that cut − music start time).
   - States `full | low | none` per `storytelling.md`, anchored to shots (`{"shot": i, "at": dt, "state": ...}`) so they follow re-timed cuts.
   - One cue covers a story section (3–5 min) with low / none pauses inside; when the song is shorter, it comes back after a pause from a fitting phrase, or another song from the same palette takes over. Never loop a stretch. Check every section against its track length before rendering.
   - Snap montage cuts: `~/.venvs/tts/bin/python scripts/snap_to_beats.py <edl> <first_cut> <last_cut>` — max half a beat, speaking shots only grow. Keep a `*.before-snap.json` copy; re-snap from it, never twice on the same file.
6. **Look & transitions**
   - Grade: EDL `"look": "film"` (soft S-curve, teal shadows / warm highlights, very light vignette, fine grain). Underwater footage is auto-detected and corrected **per clip** — one set of parameters for every shot of a clip (per-shot grading made the same turtle clip jump colour between two shots) (`scripts/grade.py`: red compensation, white balance toward tropical-blue water — never neutral grey, luminance-led stretch, light denoise/sharpen). Override per shot with `"grade": "underwater" | "none"`.
   - After changing any grade parameter, make a before/after board (`python3 scripts/grade.py out.jpg <clip>:<t> ...`) with shallow water, deep blue water, a face and coral, and look at it.
   - Transitions generated in code: `"fx": [{"type": "leak", "cut": k}]` (warm edge glow over a cut; 1–2 per minute, at section changes), `"fade_from_black"` on a shot. Outside footage only when code can't do it (`docs/footage-sources.md`); log licences in `footage/LICENSES.md`.
   - One-line text cards and the title are centred. Stamps and 花字 get a `y` on a calm area (sky, water), never over a ship, a face or signage.
7. **Build the EDL in code for anything longer than a minute** — a project `build_*.py` using `scripts/edl_builder.py` (`Builder.talk / vo / shot / photo / place / card / music / music_out / music_state / leak_before_next / steady / speech_ok / end_on_last_bar`). Hand-written JSON does not scale to 150+ shots.
   - `vo` B-roll items: `(clip, start[, audio[, seconds]])` — `seconds` fixes that item's length (a clip with only a short steady window, e.g. c065's 3 s of turtle) and the other items share the rest; `start='next'` continues the take where the previous item ended (two items over one long take); `start=None` picks the steadiest unused window. Paragraphs are long now, so a 20 s paragraph over two clips asks for 10 s steady windows: list them first (`motion.best_windows(m[clip], d, drone=...)`) and place the paragraph on them.
   - `back=True` (on `shot` / `photo` / `talk` / `vo`) skips the time-order check **and does not move the clock**, so one out-of-order shot (the user put an afternoon clip into the morning dive) does not make every later shot "go back in time".
   The builder raises `EditError` on:
   - a source second used twice (duplicates count as one clip), or teaser clips reappearing in the body;
   - going back in time > 2 min in the body (`back=True` for a deliberate flashback);
   - shaky / rolling B-roll, drone moves that reverse (see Look → Motion; `motion_ok='why'` / `allow_motion` after looking);
   - on save: a title card on screen together with a subtitle (put it on a quiet shot); narration over audible speech in the picture (checked against transcripts, Whisper hallucinations filtered); a soundless shot where no music plays;
   - `talk()` pieces: each edge moves to the silence around the speech found in the audio (at least 0.25 s before, 0.7 s after) and pieces < 1.2 s apart merge. It **refuses** a piece whose first syllable falls in the action cam's muted first ~0.48 s ("找到 Inner Peace" heard as "到…"), a subtitle word that is not heard in the piece, or an edge inside an utterance (the captain line cut to "…特别无所谓地在这钓"). `SPEECH_WARN=1` lists all problems at once; `b.speech_ok(clip, t, 'why')` passes an edge you checked by ear. Cut lines the user asks to remove (instructor asides, misspoken numbers) by splitting `talk` pieces around them; when the film is too long, drop whole exchanges, never half a sentence.
   Subtitles never overlap: the renderer ends each line before the next starts. The user talking = no narration.
   - **Transitions**: dissolve (`xfade=0.8–1.0`) only for a new day, island or town (a new place in the same area gets a bridge instead, `storytelling.md` → 场景之间怎么接); inside a scene hard cuts with sound bridges: `jcut=0.8` (the shot's sound starts under the previous picture) / `lcut=1.0` (its sound runs on under the next) on `shot`, `talk`, `vo`. Bali v1 dissolved every clip change (`soft=0.35`) and still felt abrupt because sound and picture changed on the same frame. End with `b.end_on_last_bar(after=1.5)` before `save`: the last song plays out to its own ending, then 1–2 s of natural sound. Sound effects: natural sound first, no literal foley, at most one soft riser into a big cut (`storytelling.md` → 音效).
   - **Aerial only for big scenes**: every drone or stock aerial shot says why with `aerial='first' | 'shape' | 'end' | 'title'` (on `shot()` or a `vo()` dict item); save fails on a missing reason, three in a row, or more than two at one place (counted between `place()` stamps).
   - **No-narration moments**: `b.quiet('why', seconds)` on the next shot, or `vo(..., lead=5, quiet='why')` for the first look before the narration. Narration on one fails the save; five minutes without 20 s free of words is a warning. `narration_script.py` lists them for the user. A cut made before these rules builds with `b.legacy_rules('why')` (aerial problems become warnings).
   - **Shot length follows weight**: `vo()` B-roll items can be dicts `{clip, at, w, sec, audio}` / `{photo, w, news}`; the strong shot gets w=2–3, a passing cutaway w=0.6. Equal shares read as a metronome (user, 2026-10-24); save warns on 4 similar B-roll lengths in a row.
   - **Openings / titles / stamps / endings follow the user's own episodes** (`docs/storytelling.md` → 整体结构 / 画面文字): trailer narration over one best shot per stop, then `b.card(cn, kind='title', style='stamp', latin=...)` (worn Lilita One + Noto Serif SC Black, glyph by glyph); `b.place('罗威纳', '06:10')` lower-left stamps; no chapter cards; the ending repeats the title over a wide shot. 花字: `kind='pop'` card, at most one per punchline. News: a `photo` with `news={'bg': [clip, t], 'hl': [x0,y0,x1,y1]}` becomes a paper clipping over our own blurred footage.
   - Night photos (mean luminance < 45) are lifted automatically (denoise + autocontrast) so fireflies and tree lines read; still keep a near-black series to 2–3 photos.
   - Photos: `b.photo(pid, dur, caption)` or `('photo', pid)` inside `vo(broll=...)` — shutter sound, white flash, the plain photo fitted on black (no blurred backdrop, no border — the user swapped v7's framed photos for plain ones and confirmed it), slow push-in. 2–4 in a row, never inside a live performance.
   - Fonts: **young type only** — no brush calligraphy, kaishu or formal scripts (the user called them 老气; removed from `fonts/` 2026-10-22). Catalogue and what each face is for: `fonts/README.md` (all OFL / Apache).
8. **Preview** — `PATH=/opt/homebrew/bin:$PATH python3 scripts/render_preview.py <edl> <out.mp4>` (1080p from the originals). Exit code 1 = verification failed: **do not send it**. Shots render in parallel (`--workers 6`; ~1 s of render per second of film), each with its own overlays. It checks audio length = video length, every planned cut lands on its frame (frame-difference test; ffmpeg scdet misses cuts once grain is on), every live-sound shot within 40 ms of its source, and that every light leak visibly warms the frame.
   It also checks loudness (−16.5…−12.5 LUFS), true peak (≤ −0.5 dBFS), voice ≥ 15 dB over music on every talking shot, and no silent stretch.
   Then look at one frame per shot (`python3 scripts/contact_pages.py <render.mp4> <dir>` → contact pages of 30 shots), every text card / stamp mid-way, and every leak at its peak, and measure music under narration vs. music alone before sending. On the first full Bohol cut this pass caught a black clip, a vertical ceiling shot, someone else's group photo and 8 s of night-time black — none of which verify can see. A passing verify is not a look: the leak was "present" but a cheap full-frame wash, and a stamp sat on top of a ferry.
   - External drive keeps dropping: `python3 scripts/cache_sources.py <edl> <dir>` copies the clips the EDL uses (resumable), then render with `--sources <dir>`. Without it the renderer waits up to 5 min for a missing file, stops at the first failed shot, and reuses finished shots from `<out>.parts/` on the next run.
9. **Iterate in small pieces** — after a change, render only that section (`--shots A:B`: one section of the full EDL, music seeks to the right place; 2.5 min ≈ 4 min) and send it as a preview; start the full render in the background at the same time. Size: 1.7 GB / 15 min at the 16 Mbps cap is the floor for noisy underwater footage without visible loss (VMAF 89 at 12 Mbps, x265 no better).
10. **Deliver with the narration script** — `python3 scripts/narration_script.py <edl> <render.mp4> <project>/narration_script.md "<title>"` exports (timecode, paragraph, its length read in one breath; the user's own live lines shown as quotes) next to the cut. The user records one take per paragraph reading from the script, not from the subtitles on screen.
11. **Hand-off to Jianying (works on 剪映专业版 11.6 Mac, 2026-10-16)** — `python3 scripts/export_jianying.py <edl> "<draft name>" --replace` (~15 min, mostly pre-grading). The user quits Jianying first (⌘Q); the script waits for that before writing. What we learned:
   - Jianying opens plaintext drafts (it encrypts them on its first save); the draft must be registered in `root_meta_info.json` or it is not listed.
   - The Mac App Store build is sandboxed: media on the Desktop / in Documents show "暂无访问权限 / 媒体格式不支持". Everything goes to `~/Movies/JianyingPro/Claude素材/<project>/`.
   - Anything Jianying cannot reproduce is made beforehand: graded shots with 2 s handles, the renderer's own subtitle / card PNGs (exact size, box, corners, fonts; plus an SRT for editable text), levelled music WAVs (Jianying volume > 100 % is not possible), plain photos on black with push-in keyframes and shutter sound, leaks in 滤色 blend.
   Small changes the user makes in Jianying; structural changes come back here and are re-exported.
   - **Replacing the previous version's draft** (2026-10-20): `--remove "<old draft name>"` moves the old draft to the Trash and drops it from the draft list once Jianying has quit (never while it runs — it rewrites the list on quit). Before exporting, move `~/Movies/JianyingPro/Claude素材/<project>/` to the Trash too: graded shots are cached by shot number, so a new cut would silently reuse stale clips and grades, and the folder had grown to 60 GB (53 GB of it a `footage/` copy left from the first export method). A fresh export is ~7.7 GB. Back up the old draft's `audio_record/` (the user's recordings) into `projects/<trip>/recordings/` first. The user empties the Trash.
   - **Reading their Jianying edits back**: the saved draft is encrypted, so ask for their export and run `python3 scripts/compare_cut.py <our render> <their export> <project> [first_clip last_clip]` — picture stretches that differ (with the source clip + second of each replacement, matched on proxies), subtitle-strip edits, black frames, loudness. Transcribe the export for their recorded narration. Then carry every edit into the build script before re-exporting, or the re-export wipes their work. On v7 it found: all photos swapped for plain ones (no blurred backdrop / border), 0.5–1 s black frames at photo joins, Napaling and Momo shots swapped for shots with people, and their export at −19 LUFS with a +0.1 dBFS peak (ours −15.2 / −1.3).

12. **Publish (Xiaohongshu)** — read `docs/publishing.md` first. **Cover** (3:4, 1080x1440): ask for the user's earlier covers and keep the account's frame (this one: three full-width strips, "Tony Vlog", the 搓泥…环游记 series name), then apply what reads as 高级 — one huge hero word (English place name or "Vlog") with tiny tracked labels, the subject in front of the hero word, few words, strict margins, one accent colour taken from the picture, no drop shadows. Build it with `scripts/cover_kit.py` (`Kit` for graded frames + Apple Vision cut-outs via `scripts/subject_mask.swift`; layouts `full_bleed_hero`, `triptych_hero`, `triptych_signature`) from a few calls in `projects/<trip>/publish/make_covers.py`. Frames come from the original footage at moments the user's final export still contains (fingerprint check as in `compare_cut.py`). Type: young faces only, from `fonts/README.md` (`scripts/font_specimen.py` shows simplified / traditional coverage; `check_glyphs` fails on a missing glyph). Look at every cover at feed size (180x240) and offer 3 directions. Rejected along the way: a generic big-slogan cover, brush calligraphy (老气), medium-size shadowed handwriting; chosen for Bohol: the user in front of a yellow BOHOL across the middle strip. **Copy**: title ≤ 20 characters (2–3 options), caption ≤ 1000 (opening lines on the film's through-line, the highlights, practical info gathered from narration and talk, one honest question), ≤ 10 topics. Commercial songs are never ripped from YouTube (see Copyright in `docs/publishing.md`).

## EDL

See the docstring of `scripts/render_preview.py`. Subtitles reference a shot and *source* times; cards reference a shot and seconds into it — both survive re-timing. Audio per shot: `live` (dialogue, full), `ambient` (−18 dB), `mute`. Shot keys also: `grade`, `fade_from_black`. Top-level: `look`, `typewriter`, `fx`, `vo`, `music` (list of songs with `from_shot` / `to_shot`).

## ffmpeg rule

Keep each ffmpeg call small: audio is mixed in Python and loudness-normalised on its own; overlays are one pass; leaks are another pass; then mux with stream copy. Two silent failures came from cramming everything into one graph (24 s of audio dropped; leaks never drawn).

## Publishing

The public copy lives in its own repo (`~/Documents/vlog-edit-skill`, own history) → github.com/xingtongtony/vlog-edit-skill (public). After changing the skill, docs or scripts: `python3 scripts/publish.py --push`. It copies an allow-list only (skill, docs, scripts, fonts + licences, `publish/README.md`); `projects/` never goes out (faces in contact sheets, private transcripts, local paths), and it refuses to publish if a file contains a local path, the user name or the git e-mail.

## Asking the user

Write options from a neutral point of view ("我来挑" / "你来挑"), never "你自己挑一首给我" — it was read both ways and cost a round trip.
